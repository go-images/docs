性能

性能 — go-images/images と scikit-image / SciPy の比較

基準: 同じマシンで、現実的な画像サイズを用い、意味が一致する演算について、公平で正直な計測を行います。勝っている結果も負けている結果も示します。「on n’a pas le droit de se tromper」。見せかけの勝利は、本物の敗北よりも悪いからです。

方法

  • ハードウェア: Tart の debian VM（aarch64（arm64）Linux、カーネル 6.12、4 vCPU）1 台です。両方のスタックを、同じ VM 上で続けて実行します。
  • 画像: 決定論的な 512×512（および 1024×1024）の RGB(A) 画像です（xorshift / NumPy の乱数生成器）。
  • go-images: Go 1.26.4、GOWORK=off、go test -bench を使い、時間は ns/op（計測した反復のうち最良の値）です。色の演算は RGBA で実行し、比較対象は、一致する演算を 3 つの色チャンネルそれぞれに対して実行します。
  • scikit-image / SciPy: Debian のシステムパッケージ（python3-skimage 0.25、python3-scipy 1.15、python3-numpy 2.2）を使い、time.perf_counter で、ウォームアップ後の 20 回のうち最良の値を採ります。ここでの NumPy は、SIMD を使うシングルスレッドの C です。
  • 意味の一致（比較を公平にしている部分です）:
    • ボックスブラー 半径 5 ⇔ チャンネルごとの scipy.ndimage.uniform_filter(size=11, mode="nearest")。
    • ガウスぼかし σ=3 ⇔ チャンネルごとの scipy.ndimage.gaussian_filter(sigma=3, truncate=3, mode="nearest")（こちらの半径が ceil(3σ) であるため、truncate は 3 です）。
    • Sobel ⇔ 輝度プレーンに対する skimage.filters.sobel（勾配の大きさ）。
    • Erode/Dilate 半径 2 ⇔ チャンネルごとの scipy.ndimage.grey_erosion /grey_dilation(size=(5,5), mode="nearest")。

負荷の高い分離可能なカーネルは、現在 SIMD の内側ループとマルチコアのタイリングで動作します。

  • 積和（axpy）SIMD カーネル、つまり連続した float64 プレーンに対する dst[i] += a*src[i] が、ガウスの分離可能な畳み込みを担います。チャンネルを連続したプレーンへデインターリーブしているため、カーネルの各タップは 1 回の平坦な axpy になります。2 つのパスの間のバイト丸め済みの中間結果は変わらないので、数値出力は従来のスカラコードと同一です。
  • 要素ごとの最小/最大 SIMD カーネル、つまり dst[i] = min/max(dst[i], src[i]) が、同様に連続したプレーン上で、分離可能なグレースケールモルフォロジーを担います。
  • マルチコアのタイリングは、ピクセル数のしきい値を超えると、独立した行（水平パス）と列（垂直パス）を GOMAXPROCS 個のゴルーチンに振り分けます。しきい値未満ではシリアルのパスが動きます。結果はワーカー数に依存しません。

アーキテクチャごとの SIMD の対応状況（go-fft / go-ndarray が文書化している、マルチアーキテクチャの方針です）は次のとおりです。amd64 SSE2、arm64 NEON（axpy は VFMLA を使います。Go アセンブラにニーモニックのないベクトル倍精度の FMIN/FMAX は、生の命令語として出力しており、エンコーディングは実機で検証済みです）、s390x z/vector（VFMADB + VFMINDB/VFMAXDB。ビッグエンディアンですが、これらの要素ごとのカーネルはレーン順序に依存しません。オペランドの順序は qemu-s390x で検証しています）。loong64 / ppc64le / riscv64 では、Go アセンブラに使えるベクトル倍精度演算がなく（riscv64 の場合は、既定の qemu CPU で V 拡張がフォールトします）、スカラの内側ループにマルチコアのタイリングを組み合わせています。それでもマルチコアによる高速化は得られます。SIMD カーネルはすべて、スカラのオラクルとビット単位で一致することを検証しています（axpy は、GOAMD64=v3 のビルドではオラクルが VFMADD に融合されるため、厳しい許容誤差での比較です）。演算全体は SciPy に対して検証しています。

フェーズ 1 のエッジ / フィルタの追加分 — 512×512（arm64 Linux、値が小さいほど高速）

これらは新しいマルチコア（スカラの内側ループ）の演算で、同じ VM 上で、意味が一致する scikit-image / SciPy のリファレンスと比較して計測しています。まだ SIMD の内側ループはなく、高速化の要因はマルチコアへの分散と、より安価なアルゴリズム（メディアンでの計数による選択）です。それでも scikit-image をすでに上回っています。

演算go-images (ns/op)scikit-image / SciPy (ns/op)高速化
Scharr（大きさ）1,421,7733,833,1472.7× 高速
Canny（σ=1）10,086,76827,031,5722.7× 高速
Median（r=2、5×5）37,565,475214,597,3605.7× 高速

意味の一致は次のとおりです。Scharr ⇔ 輝度プレーンに対する skimage.filters.scharr、Canny ⇔ skimage.feature.canny(sigma=1, low=20, high=40)、Median ⇔ チャンネルごとの scipy.ndimage.median_filter(size=5, mode="nearest")。Prewitt と SobelMag は Scharr のカーネルを共有します。UnsharpMask/Sharpen は GaussianBlur に、融合したピクセルごとの加算を組み合わせたものです（上記のガウスの数値が当てはまります）。メディアンの大きな差は、SciPy の汎用 n 次元メディアンに対する O(window+256) の計数による選択で生まれ、マルチコアのタイリングがそれをさらに広げています。次のベクトル化の対象は、エッジ系と Canny が共有する SIMD の Sobel 勾配カーネルの追加です。

「変更前」の列はスカラのシングルスレッドカーネル、「変更後」は SIMD + 4 コアです。以前の 2 つの負けは、どちらも勝ちになりました。 ガウスは 0.92×（1.08 倍遅い）から 3.8× 高速に、Erode/Dilate は約 0.9× から 6.7×/7.4× 高速になりました。すでに勝っていたボックスブラーと Sobel は差を広げています（マルチコアのタイリングだけで、4 コアでおおよそ 3 倍になります）。

1024² では、scipy が大きな中間配列を実体化する演算（モルフォロジー、ガウス）で差が広がります。Sobel が 1.9× に縮まるのは、ピクセルあたりの演算量が小さく、高速化の大半がマルチコアへの分散によるものだからです（このサイズでは、SciPy のエッジフィルタは 1 回で済み、チャンネルごとの Python のオーバーヘッドもありません）。

コンポーネントごとの高速化（512²、変更前 → 変更後）

  • ガウス — スカラの下限より 3.0× 高速（さらに SciPy も上回りました）。axpy SIMD カーネルが密な積和をベクトル化し、2 つのパスがコアに分散されます。垂直パスは、連続した行全体に対する純粋な axpy です。水平パスは内側の列をベクトル化し、境界でクランプされるわずかな列はスカラで処理します。
  • Erode/Dilate — スカラの下限より約 8.7× 高速: ウィンドウごとの移動最小/最大が、プレーン上の連続した SIMD の MIN/MAX とマルチコアのタイリングになり、行ごとのスクラッチ領域は内側ループの外へ出しました（割り当ては 1 回あたり約 6,200 回から 71 回に減りました）。

更新 — O(1) の van Herk / Gil-Werman モルフォロジー。 モルフォロジーの内側ループは、その後、O(radius) の畳み込みから O(1) の van Herk / Gil-Werman の移動最小/最大に書き換えられました。1 ピクセルあたり 3 回の比較で、半径に依存しません。シングルスレッドの scikit-image 同等性ベンチマーク（Apple M4 Max）では、erode/dilate は 4096² で scikit-image の 同等 → 1.02× に達し（従来は 0.58–0.77×）、全コアでは 4.8–7.8× です。出力は scipy.ndimage.grey_erosion/grey_dilation とバイト単位で同一のままです。小さい半径での残りの差は、純粋な定数倍（SIMD）です。シングルスレッドとマルチスレッドの同等性の全表と方法論は、BENCHMARKS.md を参照してください。

更新 — 分岐なしの Sobel。 ピクセルごとに再計算していた Sobel の勾配（上で挙げた唯一の負けでした）は、その後解消しました。各行を、クランプでアドレス指定する境界の列と、行のベースをループの外へ出した分岐なしの内側区間に分けたため、内側では clampIndex の呼び出しが一切ありません。出力は素朴な実装とバイト単位で同一のままです。シングルスレッドの scikit-image 同等性ベンチマーク（Apple M4 Max）では、Sobel は scikit-image の 1.02–1.06× に達し（従来は 0.78–0.80×）、全コアでは 4.2–4.8× です。詳しくはBENCHMARKS.md のアクション項目 B を参照してください。

SciPy に対する正しさ（速度だけではなく）

同じ VM で、決定論的な 64×48 の画像を使い、SIMD/マルチコアへの書き換え後の go-images の出力を、意味が一致する SciPy のリファレンスとピクセル単位で比較しました。

演算max |Δ|mean |Δ|判定
ボックスブラー00.000完全一致
Erode00.000完全一致
Dilate00.000完全一致
ガウス10.0791 LSB 以内で一致（丸めのみ）

SIMD/マルチコアへの書き換えで、数値上は何も変わっていません。ボックスブラーとグレースケールモルフォロジーは、これまでどおり SciPy とビット単位で一致します。ガウスも、最終クランプの最下位ビットの丸めだけが異なる点まで含めて、スカラ実装と同じ数値です。各 SIMD カーネルは、あらゆる長さの剰余についてスカラのオラクルとも照合しており（internal/kernels/simd_test.go）、分離可能な演算全体は、シリアルとパラレルの両方のしきい値で、独立した素朴なリファレンスと照合しています（separable_test.go）。

残る課題（正直に）

  • メモリ: プレーンベースのガウスは、従来のその場のバイト処理より多くの一時的な float64 スクラッチ領域を割り当てます（512² で ≈14.8 MB/op、従来は 2.1 MB）。これは連続した SIMD レイアウトの代償です。呼び出しごとに解放される一時的なもので、3.8× の高速化と引き換えになっています。再利用可能なスクラッチプールで減らすことは、今後の課題です。
  • loong64 / ppc64le / riscv64 はスカラの内側ループで動作し（Go アセンブラに使えるベクトル倍精度がない、qemu の V がフォールトする）、高速化はマルチコアのタイリングだけに頼っています。アーキテクチャごとの qemu CI ジョブで検証しています。

# On the arm64 debian VM, with the repo synced to /tmp/goimages:
cd /tmp/goimages

  -bench 'BoxBlur|GaussianBlur|Sobel$|Erode|Dilate|Scharr|Canny|Median' -benchtime=2s ./...

# scikit-image / SciPy side (see the harness used to produce the table):
python3 skbench.py      # timings
